에이전트 툴 카탈로그

UXERManager 에이전트(v1·v2·v3 공유)가 호출하는 전체 툴 — 기능 유형별 정리 · 대상 js/agent_tools.js · proxy/python/agent/tools_proxy.py
클라이언트 툴 66 (AGENT_TOOL_DEFS) 프록시 툴 24 (PROXY_TOOL_CATALOG) 적용 범위 v1·v2·v3 공유 (frozen 모듈)

1.개요

에이전트 툴은 클라이언트 툴(브라우저에서 ERD·UI 조작, js/agent_tools.js)과 프록시 툴(Python 사이드카에서 운영 DB 접근, tools_proxy.py) 두 레인으로 나뉜다. 둘 다 단일 소스(SSOT) 배열이라 AGENT_TOOL_CATALOG(플래너 노출)·실행 매핑·describe_tool이 자동 파생되며, v1·v2·v3 에이전트가 동일 카탈로그를 공유한다.

프론트 execTools는 툴의 kind로 처리 방식을 결정한다. 아래 종류 열은 이 분류를 따른다.

위험되돌리기 어려운 파괴적 동작(삭제·교체·DB 반영)위 종류와 병기. 신중·승인 권장.

5.아키텍처 노트

드래프트 vs 라이브 — 충돌 회피 원리
  • 드래프트는 entities/relations/layout만 담는다(_agentCloneState). 따라서 write 편집 툴만 드래프트 기반이고, 나머지(섹션·메모·스냅샷·테마·선택·뷰)는 직교 자원이라 live 직접 조작해도 드래프트 커밋과 충돌하지 않는다.
  • 워크스페이스 교체 툴(replace: 다이어그램 전환/생성/삭제·스냅샷 복원·import)은 ENTITIES/RELATIONS를 통째로 바꾸므로 ① 펜딩 드래프트 선커밋 → ② 교체 → ③ 드래프트 재동기화. 같은 턴에 편집+전환이 섞여도 유실/덮어쓰기가 없다.
  • read의 부수효과 없음: 선택/뷰/포커스/내보내기/조회는 데이터를 안 바꾸므로 드래프트 클론을 만들지 않는다(불필요한 커밋·승인 방지).
엔티티ID 비노출 원칙
엔티티ID는 내부값이다. 사용자/LLM에 노출되는 모든 ERD 툴 출력(관계 from/to·정규화 대상·FK ref.entity)은 ID 대신 _agentEntLabel()="논리명 [물리명]" 라벨을 쓴다. 라벨은 _agentResolveEntityId가 다시 ID로 되해소(괄호·대괄호 제거)하므로 후속 툴 호출에도 안전하다.
공유 frozen 모듈 — v1·v2·v3 자동 적용
agent_tools.js(클라)·tools_proxy.py(프록시)는 v1·v2·v3가 공유하는 frozen 모듈이다. 여기 등록된 툴은 세 버전 모두에 자동 노출된다 — 플래너/ReAct가 컨텍스트로 받는 AGENT_TOOL_CATALOG를 통하므로 버전 분기가 없다. (에이전트 격리 §9.1의 "의도적 공유" 레이어.)
적용·검증 메모
클라 툴 변경은 앱 새로고침, 프록시 툴·DML·엑셀은 사이드카 재빌드 후 동작. 위험 툴(delete_*·restore_snapshot·import_json·run_sql·apply_erd_to_db·manage_db_profile)은 승인 게이트 + 드래프트 안전망으로 보호된다. 실제 다이어그램/테스트 DB 회귀 확인은 사용자 검증 영역(자동화 불가).
