1.개요

현행 19툴은 단일 엔티티/관계 CRUD + 단순 조회에 집중돼 있었다. 이번 추가로 선택·하이라이트·뷰 제어 · 일괄/관계 자동화 · 구조 분석/검증 · 내보내기 · 다이어그램·섹션·메모·버전 관리까지 에이전트가 자연어로 운전할 수 있게 됐다.

2.구현 분류 체계

프론트 execTools는 툴의 kind로 드래프트 처리를 결정한다. 이를 기준으로 신규 툴을 4가지 실행 방식으로 분류했다.

방식의미커밋·상태
read상태 변경 없음(분석·조회) 또는 순수 UI(선택·뷰)드래프트 미생성. 라이브 읽기/렌더만.
write-draft엔티티/관계/레이아웃 데이터 변경_agentCloneState 드래프트에 적용 → 턴 종료 시 _agentCommitDraft 원자 커밋(undo 1회).
live드래프트와 직교한 라이브 전역(섹션·메모·스냅샷·테마·정렬·선택)라이브 직접 조작 + saveState(). 엔티티 드래프트 커밋과 충돌하지 않음(자원 분리).
replace워크스페이스 자체 교체(다이어그램 전환/생성/삭제, 스냅샷 복원, import)펜딩 드래프트를 먼저 커밋해 유실 방지 → 교체 → 드래프트를 새 상태로 재동기화.

5.아키텍처 노트

드래프트 vs 라이브 — 충돌 회피 원리
  • 드래프트는 entities/relations/layout만 담는다(_agentCloneState). 따라서 엔티티/관계 변경 툴만 드래프트 기반이고, 나머지(섹션·메모·스냅샷·테마·선택·뷰)는 직교 자원이라 라이브 직접 조작해도 드래프트 커밋과 안 부딪힌다.
  • 워크스페이스 교체 툴(다이어그램 전환/생성/삭제·스냅샷 복원·import)은 ENTITIES/RELATIONS를 통째로 바꾸므로, ① 펜딩 드래프트를 먼저 _agentCommitDraft로 현재 탭에 반영 → ② 교체 → ③ 드래프트를 새 라이브 상태로 재동기화 한다. 이로써 같은 턴에 편집+전환이 섞여도 유실/덮어쓰기가 없다.
  • read 분류의 부수효과: 선택/뷰/포커스/내보내기는 데이터를 안 바꾸므로 kind:'read'로 두어 드래프트 클론을 막았다(불필요한 커밋 방지).
§9.1 공유 영향
agent_tools.js는 v1·v2·v3 공유 frozen 모듈이다. 30툴은 세 버전 모두에 자동 적용된다. 플래너 노출은 프론트가 컨텍스트로 보내는 AGENT_TOOL_CATALOG를 통하므로 별도 버전 분기 없이 v1/v2/v3 계획·ReAct 프롬프트가 새 툴을 인지한다.
