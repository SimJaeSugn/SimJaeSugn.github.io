거의 모든 데이터 관리 기능이 동일한 상태 페이로드 { diagrams, activeDiagramId, viewMode, notationStyle, gridSnap } 를 5곳에 복붙해 직렬화하고 있으며, "저장 / 내보내기 / 백업" 명칭이 매체·역할과 어긋난다. 단일 직렬화 계층 + 명칭 1:1 정리로 중복을 제거한다.

1.현황 분석 (실제 코드 기준)

아래 기능들은 사실상 같은 페이로드를 어디에(매체)·얼마나(범위)만 달리해 저장한다.

기능함수페이로드저장 위치범위
자동저장saveState() state.js전체 페이로드localStorage STORAGE_KEY최신 1개(자동)

JSON.stringify({diagrams, activeDiagramId, viewMode, notationStyle, gridSnap}) 가 saveState · saveSnapshot · generateShareUrl · exportFullBackup(data.main) 4곳에 그대로 반복되고, exportData 만 일부 필드를 빠뜨린 채 5번째로 존재한다.

2.발견한 중복·문제

의미적 중복 semantic

① 명칭이 매체·역할과 어긋남
  • 같은 exportData() 가 메뉴에선 "JSON 내보내기", 단축키(shortcuts.js)에선 "JSON 저장" 으로 불린다 → "저장"과 "내보내기"가 혼용.
  • "저장하기"는 실제로는 선택한 다이어그램만 파일로 내보내기인데, '저장'이라는 단어 때문에 "전체가 저장된다"고 오해하기 쉽다.
  • 정작 "전체 백업"이 진짜 "전부 저장"에 해당 → 두 기능의 이름이 역할을 구분하지 못한다.
④ "버전 보관"이 3곳에 분산

되돌리기(세션 메모리) · 스냅샷(localStorage) · 자동저장(localStorage)이 모두 "이전 상태로 되돌리기/보관"인데 서로 다른 UI·저장소로 흩어져 있어, 사용자 관점에서 "버전을 남긴다"가 어디인지 모호하다.

⑤ 스냅샷이 백업 안에 중첩

전체 백업의 snapshots 그룹이 스냅샷을 포함 → "버전 모음(스냅샷)"이 "백업(파일)" 안에 들어가, 같은 목적(버전 보관)의 저장소가 이중화된다.

기능적 중복 functional

② 재검토 — "저장하기"의 필드 누락은 의도된 동작 (반영 시 정정)

반영 작업 중 가져오기 경로(handleImportFile → 다이어그램 선택 후 현재 작업본에 병합)를 확인한 결과, exportData() 는 "전체 저장"이 아니라 "선택 다이어그램을 다른 작업본에 병합하는 내보내기" 였다. viewMode·notationStyle·gridSnap 은 작업본 전역 설정이므로 전송 파일에서 제외하는 것이 옳다(가져온 다이어그램이 받는 쪽 표기법·그리드를 바꾸면 안 됨).

→ 따라서 데이터 손실 버그가 아니라 의도된 스코핑이며, 진짜 문제는 ① 명칭이다. 필드 추가 대신 명칭 통일(B)로 해결했다 ("JSON 저장/내보내기" → "다이어그램 내보내기").

③ 직렬화 로직 5중 복붙

동일한 직렬화가 5곳에 하드코딩되어, 필드를 추가하면 5곳을 동기화해야 하고 실제로 한 곳(②)이 이미 어긋났다. 단일 함수로 통일하지 않으면 드리프트가 재발한다.

3.개선안

개념 3축 정리

데이터 관리를 목적에 따라 셋으로 명확히 가른다. 한 기능 = 한 목적, 한 단어 = 한 매체.

축의미포함 기능매체
작업본 (현재 ERD)편집 중인 것의 자동 보존자동저장 · 되돌리기브라우저
버전 (이력)의도적으로 남기는 시점스냅샷 + 타임라인 + 자동저장 복구브라우저
이식/공유다른 환경·사람에게다이어그램 파일 · 전체 백업 · 공유 URL · 이미지/DDL파일 · URL

A. 단일 직렬화 계층 ②③ 근절

모든 기능이 하나의 함수로 페이로드를 만들고 복원한다.

// 신규 — 모든 저장·복원 경로가 공유
function serializeWorkspace({ scope = 'all', include = [] } = {}) { /* … */ }
function deserializeWorkspace(data, opts = {}) { /* … */ }
  • scope 로 "선택 다이어그램 vs 전체"를, include 로 "스냅샷/템플릿/설정/키 포함 여부"를 옵션화 → 저장하기·전체백업이 같은 함수의 옵션 차이로 합쳐진다.
  • exportData 도 동일 페이로드를 쓰게 되어 필드 누락(②)이 자동 해결된다.
  • saveState · saveSnapshot · generateShareUrl · loadState · restoreFromSnapshot · import 복원이 모두 이 계층을 호출 → 드리프트 원천 차단.

B. 명칭 통일 ① 해소

현재개선
"JSON 내보내기" / "JSON 저장" (혼용)"다이어그램 내보내기 (.json)" — '저장' 단어 제거, 부분 내보내기임을 명확화
"전체 백업 내보내기" / "전체 백업 저장""전체 백업 (.json)" — 진짜 백업/저장은 이것만
자동저장 (무명)상태바/툴팁에 "자동 저장됨" 표기로 노출 (기존 "변경됨" 배지 활용)
명명 규칙

"저장" = 자동저장(브라우저) · "내보내기/백업" = 파일 · "공유" = URL. 단어가 매체를 1:1로 가리키게 한다.

C. 버전 관리 통합 ④⑤ 해소

  • 스냅샷 · 되돌리기 히스토리 · 자동저장 복구를 하나의 "버전/타임라인" 패널로 묶어 노출. (이미 타임라인 HUD · 스냅샷 목록 · diff 비교가 있으므로 진입점만 통합한다.)
  • 전체 백업의 snapshots 그룹은 유지하되 "버전도 함께 백업"이라고 명시해 중첩의 의미를 분명히 한다.

D. 내보내기 메뉴 재그룹화

  • 파일 > 내보내기: 데이터(다이어그램 .json / 전체 백업 .json / 공유 URL) · 문서(이미지·SVG·MD·HTML·PDF) · 스키마(DDL) 3소그룹.
  • 파일 > 가져오기: 다이어그램 .json / 전체 백업 .json / DDL — 내보내기와 1:1 대칭.

4.적용 우선순위 · 반영 상태

#작업내용상태

③exportData 필드 "누락" (②)재검토 결과 의도된 동작 → 필드 추가 대신 명칭으로 해결정정
4버전 관리 통합 (C)스냅샷 목록·저장·비교·복원·타임라인을 단일 "버전 관리" 모달로 통합. 도구 메뉴 3개(스냅샷 저장/목록/타임라인) → 2개(버전 관리/스냅샷 저장)반영됨

불변식 (호환 유지)
  • localStorage 키(STORAGE_KEY=uxerd_v3 · SNAPSHOT_KEY)와 백업 포맷 마커는 변경하지 않는다 → 기존 사용자 데이터·백업 파일 호환 유지.
  • 기존 백업 파일(backupVersion: 3) 가져오기를 계속 지원한다.

결론: "저장하기 / 전체 백업 / 스냅샷 / 공유 URL"을 목적별로 한 번씩만 존재하게 하고, 내부적으론 단일 직렬화 계층을 공유시킨다. 우선순위 1·2번(명칭 통일 + 누락 수정)은 즉시 적용 가능하다.
