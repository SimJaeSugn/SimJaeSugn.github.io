에이전트 Client 툴 추가 계획

UXERManager · 작성일 2026-06-06 · 대상: js/agent_tools.js (AGENT_TOOL_DEFS)
ERD 시스템이 제공하는 사용자 기능 중, 에이전트가 자연어로 호출하면 유용한 것을 전수 조사해 새 Client 툴 후보로 정리한 계획서다. Client 툴은 브라우저/Electron 렌더러에서 ERD 상태·캔버스·UI를 직접 조작하는 툴로, interrupt로 프론트에 위임되어 실행된다(서버/DB 불필요).
격리·공유 주의(§9.1): js/agent_tools.js는 v1·v2·v3 에이전트가 공유하는 frozen 모듈이다. 여기에 툴을 추가하면 세 버전 모두에 자동 적용된다(과거 set_cardinality·normalize_check·lookup_std_term·register_std_term 추가와 동일한 "의도적 공유" 방식). 따라서 본 계획의 모든 툴은 시그니처·반환을 신중히 설계해 세 버전 어디서도 안전해야 한다.
✅ 구현 완료 (2026-06-06) — 본 계획의 제안 툴 30개 전부를 js/agent_tools.js AGENT_TOOL_DEFS에 구현·등록했다(기존 19 + 신규 30 = 총 49 툴). 공유 모듈이라 v1·v2·v3 에이전트에 자동 적용되며, 프론트 execTools가 종류(read/write·draft/live)에 따라 실행한다. 전체 현황·분류는 → docs/plan/클라이언트_툴_현황.html.

5. 구현 가이드 · 주의사항

5.1 공통 규약 (기존 툴과 동일)

  • 드래프트 메커니즘 재사용: write 툴은 _agentCloneState()로 복제한 드래프트에 작업하고, 턴 종료 시 _agentCommitDraft()로 커밋한다(원자성·undo 보장).
  • 카탈로그 등록: AGENT_TOOL_DEFS에 {name, kind, danger, desc, params, detail, run} 형태로 추가. run(state, args, idRemap) 시그니처 준수.
  • read/write·danger 구분: 삭제·복원·교체 류는 danger:true → 승인(approve) 게이트를 거친다.
  • async 지원: 표준사전 등 비동기 작업이 필요하면 run을 async로(execTools가 await함).
  • 사이드이펙트 트리거 툴: export_diagram처럼 파일 저장/다운로드를 부르는 툴은 드래프트와 무관한 "직접 실행" 분류로 두고, 결과만 보고한다.

5.2 격리·하네스 영향 (반드시 점검)

  • 공유 적용(§9.1): agent_tools.js 추가는 v1·v2·v3 공통이다. 새 툴은 세 버전의 execTools(agent_panel.js·client_v2.js·client_v3.js)에서 동일하게 호출되므로, 버전별 분기 없이 동작해야 한다.
  • feature-dev 하네스: UXERManager 기능 변경이므로 단축키 동기화·백업 통합 검증 대상이다. 새 툴이 상태를 바꾸면 백업/스냅샷·undo와 정합해야 한다.
  • 프롬프트 노출: 계획(plan/react) 프롬프트가 새 툴을 인지하도록, 카탈로그 텍스트·REPLAN done-목록 등 필요한 곳에 반영한다(특히 read 툴 사용 가이드).
  • README 동기화: 툴 추가는 기능 변경이므로 README.md 에이전트 기능 설명에 반영 검토.

5.3 설계 시 결정 필요

  • 선택·하이라이트의 지속성: 에이전트가 선택한 상태를 턴 종료 후에도 유지할지(사용자가 이어서 작업) 여부.
  • 대상 식별: 다수 툴이 ids 또는 keyword로 대상을 받는다 — id 미상 시 find_tables/select_entities로 먼저 해소하는 흐름 권장.
  • 일괄 작업 범위: "선택된 것" vs "키워드 매칭" vs "전체" 중 기본값과 안전장치(전체 수정 시 확인).
